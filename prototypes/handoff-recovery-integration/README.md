# 可丟棄整合原型 v3：交接看管範圍 × 暫停／恢復

**用完即丟、純模擬。**不是框架程式碼，也不是 API 提案。開啟 `integrated.html` 即可。

## 問題
宿主明確持有的交接看管範圍（ADR 0003 Q133／Q134），和 UI 暫停／恢復能否合作：視覺關閉後仍安全收尾、擋住不安全的共享資源重用、普通容量滿時仍能遞送控制訊息、每筆容量預留只歸還一次？

## 結構
- `<script id="prototype-model">`：不碰 DOM 的核心，匯出 `globalThis.IntegrationPrototype = { World, guides, runGuides, newWorld, run, CAP }`。`World.dispatch(action)`、`snapshot()`、`invariants()`；所有動作在模擬的擁有者執行緒上依序執行。
- `runGuides()` 回傳每個引導的逐步結果、不變式錯誤與預期檢查；可抽出這段 script 用 Node `vm` 執行。這是示範用的預期，不是測試套件。
- `<script id="shell">`：頁面外殼；引導與自由操作用同一批動作物件。

## v2 行為（fixture 安排，未核定為公開介面）
- **環境啟用預留**：關閉後，只有在該環境自己的排隊動作、命令、結果與恢復嘗試都結束後，才歸還一次；控制生命週期顯示「收尾中」→「已結束」。故障時預留轉給交接，之後只依「確認＋回呼安全結束＋工作結束＋租用歸還」歸還。
- **有界登記表**：途徑表只回收「已失效且無人引用」的項目；全是有效途徑時拒絕安裝（不先長大再檢查）。服務表只回收「不可信、無租用、無人引用」的項目。別名表滿時淘汰最舊的別名（別名只是展示用，不是義務）。
- **控制通道與重送票**：通道滿時取一張送方重送票保留原訊息；重送票也滿時明確回報「未受理、未保留」，訊息仍歸呼叫端。
- **停止派送**：只有投遞、重送、停止／恢復派送可執行；其他動作只增加「沒有進展」計數與日誌。恢復派送不會自動推進或重新開放 UI。
- **完成訊息的身分**：回呼結束、工作結束、租用歸還都必須帶相同的 World、交接、指派，以及唯一的工作／租用身分；ID 含 World 前綴，不跨 World 碰撞。
- **回條**：在受理動作或開始命令之前預留；記錄終態與「目前」UI 處置；只在明確收取時歸還額度。關閉不會隱含收取。
- **故障**：排隊動作逐筆「未執行」、已開始命令請求取消、進行中的恢復嘗試失效。共享服務不可信時，fixture 假設其他環境的資料仍健康、只是資源被擋，需驗證新資源與隔離後才能恢復。
- **共享故障後的隔離證明**：服務被宣告不可信時，所有依賴它的其他環境（不論當時是執行中或已暫停）都標記「需要明確證實隔離」，先前的「已證實」宣告作廢。改綁新服務只換資源，不等於證明；恢復條件依序擋下「隔離未知」「仍依賴不可信服務」「尚未證實隔離」。只因接收途徑失效而暫停、沒有共享故障的環境不受此要求。
- **改派**：已確認後拒絕；確認不等待外部業務修復完成。
- **不安全收尾**：已關閉且宣告不安全時，完成或取消的結果都保留，不立即處置；即使環境閒置，也保留啟用預留與「收尾中」，要等宣告安全後在擁有者動作中才結束。
- **晚到結果（實驗性規則）**：恢復期間在本批之外結算的結果，提交時仍保留；重新開放後由 `processPendingResults`（每次最多 2 份、每次重新驗證途徑／資源／狀態）處置一次。暫停中拒絕執行。這不是一般排程器。

## 限制
- 作者只有靜態追蹤；執行證據以 Codex 的紀錄為準。沒有瀏覽器手動走查。
- 沒有真實宿主、執行緒、GPU、致命終止；隔離與收尾安全都是宣告，不是偵測。
- 沒有改變「外部資料版本」的動作；故障不會讓共用服務的其他環境也變成故障，只會暫停它們。
- 不提供跨看管範圍移交（第一階段不可用）；候選失效只做最簡單的「改派失敗、舊資格不恢復」。
